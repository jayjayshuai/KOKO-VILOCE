# 阶段开发与代码提交计划

用户要求持续完整开发、阶段性提交到既定仓库。沿用企业路线与语音房计划，
代码提交/远程推送/服务器发布分别记录，不因提交成功勾除正式上线门槛。

## 提交规则

每批是可回溯的业务增量：实现、接口/字段中文注释、前后端错误与恢复、相应测试、
格式及敏感信息检查同时提交。提交前核对真实暂存blob和历史；不加入.env、私有服务器
配置、备份/SQL导出、运行目录、日志、密码或令牌。保留已发布迁移，不强推、不重写历史。
阶段存在缺口时在交付记录明确，不能写成生产验收通过。

## 执行顺序

1. 聊天多实例候选：V4同事务同步版本、当前成员读、明确WS发现路由、Cookie/会话轮次、
   Redis连接租约及前端恢复一起提交；先复验全量构建/格式/隐私，再推送。
   已有真实SQL/双Netty、完整Gateway网络、局部页面和配额证据各自保留其范围；未部署。
2. 语音房主工作台：本人房间游标列表、状态/关闭操作、前端权限与异步轮次隔离，
   配套OpenAPI/字段注释、SQL索引、测试及真实SQL验证；不冒称麦位或在线成员已实现。
3. 语音P1：独立房间成员/角色、席位全状态机、幂等/租约/审计、服务器LiveKit授权及补偿，
   房间事件与前端管理面板；实际SQL竞争、媒体失败和双端验收后分批提交。
4. 可靠运维：外部告警/真实推送、异地备份恢复、完整管理权限与内容处置/申诉。
5. 商业及整体验收：Discord/视频不因方向建议删除；资金功能须真实支付适配和对账，
   缺供应商或审批不伪造成功。最后完成TLS、容量、发布/回退和上线检查。
