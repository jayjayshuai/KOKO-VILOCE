# 聊天跨节点同步验证 · 2026-10-05

结论：本批源码、局部回归、真实隔离 MySQL 与独立 Netty JVM 网络验证通过，**未发布**。
不是完整企业上线验收；不证明语音房事件总线、真实共享登录或生产容量。
按照项目企业开发规范执行先验证不变量、保留失败证据、限权隔离和备份后清理。

## 已实现

- Java/MP XML 的用户级持久同步版本与消息/成员/群名/解散/本人已读/本人拉黑同事务。
  版本写失败回滚业务；按用户升序锁，最多 50 人，不建全局版本热点行。
- Netty 节点独立单线程读取本机认证用户，单批 100，默认间隔 1000ms；
  仅向变化用户推无正文 SYNC，失败不推进该批进度，启动/重启从数据库重取。
  生命周期围栏、有界 SQL 超时、无用户标签指标、安全状态转换日志。
- 会话锁后的成员授权、同步收件人、群人数上限改用当前读。
  普通 RR 快照不等于当前成员：不能因为外层早已读取过数据而漏通知或保留踢人后的权限。
- Vue 聊天面板保存历史读取期间的同步请求；请求取消、切会话/卸载/认证失效围栏、
  焦点/可见性恢复补拉、同步中状态及独立错误反馈；恢复不清除发送/管理错误。
- 握手拒绝重复可信身份/密钥/Origin/Cookie 头、非规范正数身份和重复会话 Cookie。
  不把同名 Cookie 解码后任意选出的令牌作为登录事实。

## 真实数据库与网络

本机官方 MySQL 8.4.11，环回独立监听；每轮新数据目录，非 Windows 服务。
测试账号仅授权两个固定合成库，无全局权限。密码随机生成、只在进程环境/输入中传递，
不写入源码、证据或命令参数。未连接或修改用户部署服务器。

官方 Windows ZIP 的下载页 MD5 与实际文件一致：`2e833921898a9a030ea6bfe81bd811bc`。
实际 ZIP SHA256：`a492371d687d2bab088b0062581144a0044b8964baefdf4faa579292b423d25c`。
Flyway 成功应用并验证 V1～V4；原 V1～V3 未改。MySQL 8.4 高于当前 Flyway 验证过的 8.1
警告保留；兼容性仍按本批实际 SQL 结果判断，不泛化到其他版本。

旧 `ChatMysqlCheck` 六组回归全部通过：24 并发发送/幂等/序号、拉黑和证据、举报配额20、
审核并发/审计失败回滚、拉黑配额1000与 RR 竞争、2205条历史扫描/收藏并发/重新入群边界。

新增 `ChatClusterMysqlCheck` 七组 SQL 检查：

1. V1～V4、真实 Spring 事务代理、MANDATORY、创建/发送/幂等/冲突的版本事实。
2. 24 并发发送、连续消息序号及用户版本，已读不倒退。
3. 两个不同会话/反向群主/重叠用户的 20 并发提交，稳定锁序没有丢版本。
4. 实际 SQL 触发器故障：后一用户版本失败，前一版本、消息、序号全部回滚。
5. 独立连接看不到未提交版本，外层事务回滚恢复群名和版本。
6. 新成员、被移除成员与剩余成员；移除后查询拒绝；拉黑只通知本人；解散。
7. 实际外层 RR 快照 + 另一事务提交加人/踢人；当前收件人，以及已撤销的历史/发送权限。

四组真实 TCP 检查：

1. 两个独立 JVM/PID 运行生产 Netty/业务代理/SQL：A 收到已提交 ACK，B 收到
   无正文定向 SYNC，合成无关用户没有变化提示；B 可以重新读取真实已提交历史。
2. B 的观察查询实际执行缺表 SQL 并失败；A 仍提交消息；B 恢复读取后在**没有新发送**的
   情况下发现持久版本。不是停库、断网、连接超时或所有故障分支演练。
3. 改名/踢人到达远端节点；被移除人收到提示，但真实查询列表为空、历史拒绝。
4. 两个旧 JVM 都优雅退出后重新入群并提交离线消息；新 JVM 收到 READY/SYNC，
   仅能读取重新加入后的事实，不继承旧观察缓存。

身份精确限制为少量合成账号/令牌；Origin/内部密钥/协议使用生产逻辑，
但没有启动真实 Sa-Token/Redis/Gateway/Nacos 或完整 Spring Boot 集群。
轮询间隔为夹具250ms，生产默认1000ms；没有据此报告一秒端到端延迟 SLA。

## 失败与修复记录

- 初轮 Maven 参数未引用导致 PowerShell 拆开 dotted `-D`，修正引用后重跑。
- Mockito 对原先抛异常的桩重新赋值方式不正确，改 `doReturn`，未跳过测试。
- 新实际工作线程测试碰到重载 `stop` 的 `submit` 歧义，显式 Runnable 后重跑。
- 前端补拉函数增加 boolean 结果后触发 TS 操作回调类型错误，改为 `Promise<unknown>`，
  类型检查与构建重新通过。
- 本机 MySQL 首轮参数分组错误，第二轮 Windows 监视父/子 PID 导致所有权校验拒绝；
  未跳过所有权校验，检查精确子进程/目录后优雅关闭；改用 `--no-monitor` 后重新隔离验证。
- 增加 RR 测试后，修复前轮次确实失败于“旧快照漏掉新增同步收件人”。
  保留该轮日志/冻结类/SQL备份；新增当前读后，最终轮次所有 SQL/TCP 通过。

最终真实运行使用**冻结的本批编译类及资源**；未在运行中替换类。
依赖来自固定本地 Maven 缓存，证据记录 SHA256；归档不声称含完整 JDK/MySQL 二进制或
可脱离本地依赖一键恢复的运行环境。
