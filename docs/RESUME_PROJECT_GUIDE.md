# KOKO Nexus 项目介绍与演示

定位：Java 主导的创作者与社群互动平台。优先展示账号、内容、社区和 Netty 聊天的真实闭环，
语音控制面作为进阶工程内容；视频推流、Discord OAuth 和完整受控音轨撤权仍在开发。
不要将单机阶段环境写成已支撑大规模生产流量。

## 简历表述

**KOKO Nexus — 创作者社区与实时聊天平台（个人项目）**

技术栈：Java 21、Spring Boot、Spring Cloud Gateway、Sa-Token、Nacos、Dubbo、
MyBatis-Plus、MySQL、Redis、RocketMQ、Netty、Vue 3、TypeScript、LiveKit。

2026-10-07当前基线已对齐七库并发布八个后端；真实功能、通知空间故障与恢复、
Nacos发现、测试数据清理和本地断点见[最新记录](BACKEND_BASELINE_VERIFICATION_20261007.md)。
语音可展示自建服务的创建/关闭管理；受控八麦位的实际音轨仍未开放。

- 按身份、社区内容、聊天、通知、资产与语音领域拆分服务；通过 Gateway 统一鉴权，
  下游核验资源归属，使用 Nacos 注册发现和 Dubbo 完成跨服务身份查询。
- 实现创作者主页、文章草稿/发布、关注收藏、社区成员管理，以及 Netty WebSocket 私信和群聊；
  聊天支持幂等消息提交、服务端序号、历史游标、已读和成员权限隔离。
- 使用事务 Outbox 与 RocketMQ 投递通知，设计有限重试、租约、CAS 确认及幂等消费；
  验证发送成功但数据库确认失败的重复窗口，保留消费者防重和人工恢复边界。
- 采用 MySQL 版本迁移和真实 SQL/网络测试验证关键并发与越权场景；
  前端隔离各业务分区故障、取消过期请求，避免单个微服务不可用拖垮整个发现页。

实际经历由本人核对后使用。不能写尚未测量的 QPS、在线人数、可用率、提升百分比，
也不能将工具生成的代码视为自己已理解和独立完成的所有设计。

## 十分钟演示顺序

准备两个自己的测试账号和两个独立浏览器会话；使用演示环境或明确允许操作的账号。
所有数据来自实际 API，缺少数据时先创建，不添加硬编码卡片。

| 顺序 | 演示内容 | 需要观察的结果 |
| --- | --- | --- |
| 1 | 注册/登录、刷新页面、退出 | HttpOnly 会话恢复；匿名私有接口 401 |
| 2 | 建立创作者主页、保存草稿、发布文章 | 草稿仅本人可见；发布后公开发现 |
| 3 | 第二账号关注、点赞、评论、收藏 | 重复操作不重复计数；可取消；本人集合可查 |
| 4 | 创建社区、加入、查看成员、所有者移除 | 所有权约束；私密成员列表隔离 |
| 5 | 私信、建群、邀请第二账号、互发消息 | 两端接收；历史可恢复；消息 ACK 与持久化对应 |
| 6 | 刷新聊天页面、搜索/收藏历史、移除群成员 | 当前成员才能访问；重新加入不泄露原历史 |
| 7 | 查看通知、标为已读、调整接收偏好 | 真通知入箱；已读幂等；他人记录不可修改 |
| 8 | 展示一个服务失败的发现页 | 正常分区可继续读取，失败分区明确报错和单独重试 |

语音互动 SQL 状态机、随机媒体身份、撤销任务和持续信令校验可以讲实现和实验结果；
真实双浏览器音频、旧音轨清退与无绕过的公网 TLS 尚未完成时，不现场承诺其已可用。

## 本地运行入口

私有调试启动器位于 `.runtime/local-remote-debug/start.ps1`，输入 SSH 密码后启动八个本地 JVM，
通过 SSH 连接远程既有 MySQL、Redis、Nacos。IDE 以 Java 21 导入 `backend/pom.xml`，
使用忽略的 Remote Attach 配置；详细端口和停止方式见私有目录 README。

前端：

```powershell
cd D:\KOKO\web
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

`http://127.0.0.1:5173/` 是当前源码的本地调试入口。既有数据库调试保持只读、关闭 Flyway
和后台写任务；注册、发布、聊天发送等写操作受保护。远程 Schema 落后时，新源码会明确报错，
需要单独按发布流程准备备份、迁移和回退，不能通过关闭只读保护解决版本不兼容。

启动器同时提供 `http://127.0.0.1:45173/koko/`：通过 SSH 访问服务器当前已部署版本。
此入口运行远程业务、可写现有项目数据，和本地只读调试不同，使用自己的账号谨慎操作。
没有启动 SSH 转发时该入口不可用；它不代表当前工作区所有增量已经发布。

公开读取检查：

```powershell
cd D:\KOKO
npm run check:environment -- --api-base http://127.0.0.1:42880/api
npm run check:environment -- --api-base http://127.0.0.1:45173/koko-api
```

检查会分别输出五个发现接口及匿名身份边界，不打印用户数据或携带账号凭据。
退出码 1 表示存在失败；读取通过不能替代登录、持久化写入、WebSocket 或 RTC 演示验收。

## 面试前应能解释

- Gateway 验证身份与业务服务核验资源归属分别解决什么问题？
- 消息重试如何保持幂等，ACK 丢失时为什么不能当成未提交？
- 数据库事务为何不能原子包含 Broker、MinIO 或 LiveKit 调用？
- 为什么 Netty EventLoop 不执行阻塞 JDBC/RPC？队列、背压和连接上限各限制什么？
- 为什么发送后确认失败可能重复，CAS 和租约为何仍需要消费者防重？
- Flyway 增量发布、数据库备份、程序回退与数据恢复为何不是同一操作？
- LiveKit 负责音视频媒体，Netty 负责文本聊天；关闭信令为什么不能直接证明 RTP 音轨已停止？
