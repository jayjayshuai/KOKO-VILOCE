# 系统体验优化计划

本轮先闭环已被用户实际反馈的语音操作问题，再依照真实证据推进全站入口与异常体验。既有未验收改动保留，不把工作区所有修改合并发布。

## 不变量

- 明确点击“加入并发言”串行完成入房、申请和语音连接；普通成员仍由房主授权，不能自批准。
- “只收听”不采集麦克风。刷新、返回、重登录、已消费意图不自动重新开麦。
- 取消发言、离房和换身份使旧操作失效；未知提交不生成新请求伪装成功。
- 房主一次同意发言完成席位审批与允许发言；成员收到批准后仅在房间前台且保有明确意图时开始设备采集。
- 跨页面延续既有通话；不借后台挂起新增设备采集。浏览器或系统真正冻结不承诺持续运行。
- 私有生产配置不提交、不打包、不在日志或公开证据展示；不启动这些配置进行生产迁移。

## 阶段

1. 一键语音：精确候选树测试、构建；三个独立测试账号通过真实 API、Cookie、LiveKit、RTP 验证，无身份/API/SDK桩。检查申请批准、闭麦、收听、切页和离房。
2. 恢复体验：针对第一阶段发现的轮询、取消、后台恢复和状态反馈问题补回归，不让临时错误导致循环弹窗或按钮无反馈。
3. 全站入口与布局：检查登录/注册反馈、移动布局、导航及常驻条可访问性；只提交本轮范围并通过实际页面验证的源码。
4. 发布与交付：增量前端发布、独立账号线上复验、脱敏阶段记录和提交；后台不需要变更则不重启任何 JVM 或中间件。

上述四阶段在本轮限定范围内已完成，候选与线上记录见[系统体验优化验收](SYSTEM_EXPERIENCE_VERIFICATION_20261011.md)。这不是全系统已完成证明：第三阶段目前覆盖认证表单、导航、常驻条和移动布局，不包含所有业务页面。第三方 Discord、支付、视频与外部告警的供应商能力仍单独验收。

下一轮优先：分别验收创作者编辑器与通知恢复工作区改动，再推进聊天弱网恢复、可观测性及容量测试；不得仅凭本轮构建或两路音频验收勾选这些门槛。
