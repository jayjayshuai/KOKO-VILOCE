# 开源凭据审查与配置加固（2026-10-09）

按用户要求检查数据库、中间件、服务器和网站凭据，不在报告、命令参数或Git中输出真实值。
遵循enterprise-development的私有配置、实际证据和发布边界要求。

## 已检查范围

- 获取远程分支/标签清单及最新引用：远程只有main，无标签。
- 本地及已获取远程引用的11个可达提交、872个不同Git文件对象，与17个已知私有凭据值
  逐项比对；另检查未提交跟踪文件及未忽略源码。实际凭据只在内存读取，附加已知密码
  使用无回显输入，结果只记录路径/规则，不显示匹配文本。
- 比对未命中；另运行可达历史秘密规则检查。私有配置、SQL导出、日志、实验目录和IDE文件
  仍被Git忽略，提交/推送钩子拒绝强制加入这类路径。
- 不涵盖他人副本、未获取的特殊引用、外部日志/附件或未掌握的旧密码；这是限定审查，
  不作零泄漏保证，也不将启发式通过当作完整安全认证。

未发现当前真实凭据被上传的证据，因此没有强推改写历史或擅自轮换共享服务器密码。
对话中曾发送的凭据仍建议由负责人协调更换；更改现有数据库/中间件密码需同步依赖方，
不能不通知就中断共用服务。若后续发现真实泄漏，先撤销/轮换，再按精确引用处理历史，
删除最新文件不能撤回已传播的秘密。

## 本批修改

八个业务服务的数据库/Nacos密码不再包含开发默认值，仅接受私有注入；生产Compose继续
要求缺少凭据立即报错。公开.env.example只保留替换提示，不写真实环境信息。
原有公开开发默认值经本批已知凭据比对未命中，不能把它们说成当前线上密码。

秘密拦截补配置未加引号值、短密码、JSON嵌套/压缩格式以及数据库/中间件URL内嵌凭据。
当前暂存树和实际推送的分支/标签尖端同时拒绝非占位的密码环境变量默认值；
不能把旧配置提交作为新推送尖端绕过限制。历史旧变量引用保留兼容检查范围，
历史直接字面量、令牌、私钥、私有路径及已知部署信息仍检查。
Spring默认值不被误当成Compose的缺配置报错语法，代码中的中文字段说明不当作配置密码。
