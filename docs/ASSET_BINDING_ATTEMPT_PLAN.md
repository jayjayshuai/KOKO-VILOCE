# 绑定结果核对实施计划

## 不变量

- 写域在发送begin前独立提交不可变指纹的OPEN凭据，再由实际业务事务锁凭据行。
- 成功业务提交、COMMITTED凭据和PENDING释放任务在同一本地事务；任一失败全回滚。
- 已知回滚或后台核对仅在取得同一行锁且仍OPEN时，原子标记ABORTED并登记原requestId释放。
  活跃写事务持锁时跳过；ABORTED永久拒绝新的业务获取，不按时间猜测提交结果。
- 自动核对只处理新协议凭据，不对旧协议缺行意图造结束证明；无凭据仍保留。
- 核对不删除资产/对象、不退配额、不同步跨域改写；已有seal补偿与永久结束标记承接释放。
- 业务提交/回滚之后即时释放故障不能改报业务失败；故障保留持久PENDING任务。
- 只读核对必须当前专用权限、固定域、有界游标、不输出所有者/对象键/凭据。

## 阶段与验收

1. 新身份V17/社区V16凭据表，MP/复杂SQL、独立事务代理及写域接入；旧迁移不修改。
2. 后台核对默认关闭；批次最多8、SKIP LOCKED、固定OPEN→ABORTED与同库任务原子性。
3. 专用读RPC/HTTP与前端凭据列表/详情，明确OPEN不是“失败可删除”，缺行不是结束证明。
4. 本地权限/协议/前后端测试与格式/构建；真实MySQL独立事务、锁/竞争、回滚/幂等和故障恢复。
5. 新实际Provider完整网络、正向UI、备份恢复、无旧写入者混跑升级、发布与公网验收。
