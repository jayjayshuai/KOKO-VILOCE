# 常驻多人语音验收（2026-10-11）

## 已完成与发布

- 房间视图缓存与常驻通话条：站内切页不销毁当前连接，返回原房间不重发 JOIN、凭据或麦克风采集请求。仅缓存一个房间；换房、退出/更换登录轮次清理旧组件及控制入口。
- 只代理真实媒体状态，常驻 Store 不保存 JWT、Cookie 或 SDK。旧注册的状态、清理和控制闭包不能覆盖后续通话。
- 已连接通话可继续处理后台可见性事件下的核验和续约；未连接时仍暂停后台操作，离线/核验过期仍失效。
- 房主在成员列表允许/禁止发言；非房主不能调用 `MUTE=false` 自行解除房间闭麦，重新申请的麦位也默认闭麦。个人设备开关仍由本人确认。
- 管理明确的其他成员不会因为写请求在途而切断房主自己的媒体；自己的权限变化、离房和未知目标仍保守停止。
- 主动离房先停止本机采集和播放，再核验并提交 LEAVE；服务器结果未知时不能宣称已离房。

语音后端发布前活跃成员数为零；只替换经过完整摘要校验的语音 Jar，配置、数据库结构及其他服务没有改变或重启。前端随后独立发布，两次发布均保留可恢复备份，健康检查通过，未触发回滚。

## 使用与限制

房主允许成员发言后，成员在声音区连接并明确开启麦克风；多个成员可同时发声。切换站内页面后通过常驻条返回或关麦，只有主动离房才结束当前通话。被禁麦的成员可重新连接为听众，不能自行解除房间闭麦。

本次确认的是两个同时发布者与第三个收听者，不是八路压力/容量验收。手机系统冻结、杀进程、锁屏或完整文档刷新不能保证持续通话；恢复后须核验当前权限，不能自动复活旧身份或设备。浏览器冻结会暂停计时器和fetch回调，参考[Chrome官方生命周期说明](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)。

“更简洁的一键加入/申请/开麦”是后续新增交互范围，本记录不把该范围算作已经完成。
