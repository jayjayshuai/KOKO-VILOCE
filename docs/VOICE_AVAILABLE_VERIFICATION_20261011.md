# 语音网站会话闭环与可用发布验收

2026-10-11，按enterprise-development规范执行。本文只覆盖受控语音功能，
不表示视频、Discord、容量、高可用或全平台企业验收已经完成。

## 本轮实现

- V6为当前媒体绑定新增域隔离网站会话摘要及发现索引，不保存可登录Cookie/令牌。
  摘要由Sa-Token确认身份后的网关生成，删除客户端同名头，仅传给可信凭据接口。
  受控WS准入同时核验用户、签名JWT、成员/麦位、当前UUID及网站摘要，不能用同账号另一网站会话复用旧JWT。
- 首次签发声明当前网站会话，网站切换推进UUID/轮次并登记固定旧目标。
  新目标提交后先返回准备中，等待持久退场屏障；重试同网站不重复推进轮次，不先签JWT再等待。
- 注销先撤销网站会话，再按旧摘要发现、逐房短事务清理成员/麦位、审计及旧身份任务。
  迟到的旧注销找不到新摘要，不能移除新UUID。登记每批有界16房，未完整登记返回503，不冒充物理清退成功。
  WS确定网站失效时补登记，Redis状态未知只关闭信令，不把依赖异常当作确定注销。
  物理SFU移除仍由持久退场worker执行；故障、DEAD任务及运维告警是独立风险。
- 网关RPC补显式序列化白名单与固定错误响应，旧Provider不支持该方法不得静默成功。
  默认创建受控房间，页面去除“媒体待接入”旧文案；旧LEGACY房间不自动迁移，旧入口不冒充可连麦。

## 实际SQL、构建及失败修复

使用自有本机MySQL8.4限权合成测试库，先做一致性备份和SHA校验，再仅重建该合成库；
未重建其他库、扩展账号权限或在项目生产库注入故障。一次新测试库初始化因权限不足失败，
没有提权；一次新增测试签名仍指向旧夹具房间导致断言失败，保留后修正并全量重跑。
本机RTC两库迁移前另备份，独立MySQL没有因SSH中断停止。

最终十四组实际MP XML/事务代理验证通过：网站摘要声明、跨网站拒绝、轮次/旧目标、
切换回滚、迟到注销、新身份不受影响、注销审计失败整事务回滚、双worker只登记一次，
以及原有成员/麦位/角色/租约回收/退场预算/旧执行拒绝等。

第一次公网双场景并发中，一轮页面准备请求返回500，测试房间已关闭。
只读诊断确认实际MySQL死锁图：成员PRIMARY间隙锁与媒体绑定PRIMARY插入互等，
没有依据重试后通过就忽略该错误。互动/关闭事务改用显式READ COMMITTED，
仍先锁当前房间行串行同房事实，权限/版本/CAS/唯一约束未放宽。
实际双事务屏障令两个不同房间均读完空成员后同时插入，双方成员和媒体计划都提交；
同房竞争/回滚等旧检查继续通过。不能据此宣称以后永不死锁或已完成负载测试。
依据：[MySQL 8.4隔离级别说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)。
