# 通知中心可用闭环计划

- 已确认页保留，分页失败重试原页；只读重试不重发已读或偏好写入。
- 已读回应丢失按原ID锁定，只有读取到有效已读事实才能解除，不能凭未见目标或无效时间解锁。
- 偏好未知结果按类型隔离，不被其他类型的成功遮盖；三项GET成功核对后再应用。
- 同账号新登录和换身份重建页面，卸载取消请求，旧回包不能污染新页面。
- 未读筛选仅作用于已加载集合，不伪造全站未读总数；后端时间按Asia/Shanghai解释。
- 只用测试账号、新建文章和评论触发实际Outbox/MQ/通知消费，不读写现有用户通知。

阶段：源码和回归 → 精确候选/页面检查 → 实际事件投递、偏好、分页、权限及回应丢失联调 → 保留旧哈希资源发布和线上复验/提交。

2026-10-12：该阶段已完成源码、冻结候选及线上复验，具体证据和未解决范围见[可用闭环交付记录](NOTIFICATION_USABLE_DELIVERY_VERIFICATION_20261012.md)。不是把首次投递失败计为通过，也不是全站通知/容量认证。

全量未读统计、批量已读、稳定游标、外部推送/告警、MQ故障与多节点容量仍单独推进。不启动私有prod配置，不执行数据库迁移。
