# 语音房互动核心阶段验证

本批2026-10-05开始、10-06收尾，代码候选未部署。按指定企业开发规范实现真实持久状态、

## 已实现

- Voice V3新增CONTROLLED模式、单调房间版本、成员/会话、8麦位、预约、幂等收据和追加审计；
  新关闭状态CLOSING。V1/V2不改，已有LEGACY房间不转换，以免既有发布JWT绕过新控制。
- 成员90秒租约，预约60秒；数据库时钟/房间行锁/锁后当前读。过期/旧session不复活，
  操作/快照惰性回收，不声称后台定时回收、设备识别或RTC在线人数。
- APPLY/INVITE/PULL、ACCEPT/REJECT/CANCEL、DOWN/KICK/MUTE/LOCK、LEAVE、ADMIN/TRANSFER。
  预约准确绑定成员代次，邀请由受邀人确认；房管不能踢/闭其他管理者。长期房管最多8人，
  可离线撤权；HOST是普通成员在麦派生态，不能因此得到管理权限。房主转让同事务改变角色/归属。
- UUID与规范参数指纹、角色/房间版本围栏、状态/审计/收据同事务；原成功重试返回原提交，
  不再次改变当前状态。10秒最多10个新命令、每人每房间1000收据，退出可再一次；
  是保护阈值，不是容量或永久幂等承诺，生产前仍需受约束归档/保留策略。
- 审计记录原操作者/目标/席位/预约/希望值，单调版本分页；普通成员拒绝，开放时仅房主/现任
  有效房管可读，关闭后仅当前房主可读。应用只追加，不是DB管理员防篡改或全事件重放证明。
- 关闭先短事务登记CLOSING冻结归属/新入会/转让，再事务外删除媒体，最后短事务确认。
  媒体或SQL失败保留意图、允许原房间重试，不恢复OPEN或伪装CLOSED；已关闭重试不重复删除。
  新增转让不能让旧房主用提前读到的身份继续删除媒体。没有自动关闭补偿工作循环。
- Vue房主管理和受控发现入口、成员/麦位/预约/角色/审计、关闭历史；单写、未知结果原请求
  重试、读写故障分离、身份/房间轮次、卸载/心跳回收。提交后重取失败不改提交成功为失败。
  新受控创建由真实能力开关显隐，不把能力读取失败当可用。

## 明确保持关闭的媒体边界

`VOICE_INTERACTION_CORE_ENABLED`默认false，Compose显式传入候选开关；`mediaReady`固定false，
不由环境伪造true。受控房间的原入会接口拒绝签发发布JWT，前端不启动旧SDK/麦克风。
创建受控房间仍调用真实媒体编排，但这批未做该路径的完整真实服务验收。
麦位ON_MIC和希望闭麦仅为SQL事实，页面明确媒体待接入，不承诺已发声。
本批没有完成LiveKit席位发布授权、旧JWT撤销/信令入口、媒体故障补偿或实时房间事件。
前端5秒事实轮询/25秒心跳不是WebSocket事件总线，不能勾除P0/P1。
