# 媒体绑定轮次与持久退场候选验证

2026-10-06，按媒体授权计划第2～3项推进。代码候选、未服务器发布。
新V4只在独立本机MySQL实验室应用，**未迁移现有远程项目库**。
计划/退场执行开关均默认false，受控媒体准备度仍false，不签发受控JWT。

## 同事务与授权不变量

- 每名成员的媒体绑定保留单调generation、独立随机UUID和原成员session。
  上/下麦、希望发声变化、离房、重新加入、过期回收/关闭更换身份或轮次；
  仅申请/邀请、房管授予与所有者转让不自动授予发布能力。
- JOIN、核心命令、惰性回收及CLOSING意图在原房间锁/事务中登记媒体计划。
  原收据重试不重复推进轮次；任一任务写入/审计失败令整个核心事务回滚。
  记录器拒绝事务外调用，事务内不访问LiveKit。
- 旧退场任务固定原供应商房间和旧UUID，不按当前成员或新所有者重新计算目标。
  再次入房不将generation归零；旧任务重试不能删新身份。LEGACY不自动转换。
- 成员查询/计划绑定批量有界，避免每个快照逐成员查100次绑定；受控关闭前未加入的
  空房间也可记录关闭意图，不能因尚未建立八麦位阻止关闭。

## 任务领取、预算及供应商调用

四条一批、四十秒数据库租约，领取先消耗预算，最多十次。清理耗尽租约与领取分开提交；
领取使用READ COMMITTED，并把待执行/过期PROCESSING分为两个有序索引查询。
实际生产XML经EXPLAIN验证索引，无filesort。UUID租约与数据库截止的CAS拒绝旧确认/旧失败。
崩溃后的第十次过期任务转DEAD，不允许第十一次I/O；恢复不自动重置预算。

执行在独立短事务外。实际SDK设置整次调用五秒/零隐式重试，原身份删除成功后SQL确认失败
保留PROCESSING租约，不改写成供应商失败；恢复可幂等重删原身份。404只有有界、严格Twirp
`not_found`才确认原参与者缺失；HTML404/坏路径/重复code/超大响应不伪装任务完成。
定时执行仅在显式开启候选开关时安装，不因V4或前端进度查询自动调用SFU。

## 前端与接口

当前授权后读取本人轮次/希望值与全房间待退场、耗尽预算计数，不暴露内部UUID或成员session。
OPEN允许当前成员/房主，CLOSING/CLOSED仅现任房主。可信网关及no-store保持；
世代以字符串返回。诊断不是媒体授权，也不是物理在线/已清退证明。

新增独立进度面板，不影响原核心写入。协议损坏/网络失败清旧进度，不展示假零；
候选禁用与任务完成区分；切身份/房间/失权取消旧请求，离线/隐藏暂停并在前台重新读取。
定时读取有界退避、卸载清监听/计时器；拒绝客户端把mediaReady=true冒充已开放。
关闭审计也可读本人退场进度，不能因媒体队列故障伪造核心审计为空。
