# 静态前端发布兼容约束

发布后的旧页面可能仍引用原先的懒加载脚本。只备份目录而不继续提供旧哈希文件，不能保护已打开的页面；Vite 的[官方加载错误说明](https://vite.dev/guide/build.html#load-error-handling)描述了这一类版本错配。

## 必须保持的行为

- 首页、index.html 和 SPA 回退使用 Cache-Control: no-store；带内容哈希的静态文件才使用 immutable。
- 新静态目录切换前，将当前目录的既有哈希 assets 合并到新目录。文件名相同必须摘要一致，不覆盖冲突文件，不复制旧首页。
- 本轮未删除任何既有哈希文件。未来设置回收策略时，至少覆盖资源缓存期限及仍需支持的旧页面窗口；不得与发布目录切换同时随意删掉前一版 assets。
- 切换前备份并核验静态目录、Nginx 配置，先在隔离容器验证配置。失败回退时同时恢复目录与配置。
- 路由或脚本加载失败显示可见恢复入口，不输出原始异常、资源URL或凭据；不自动刷新，不重放 JOIN、写入或麦克风意图。
- 用户明确刷新前提示会结束通话及可能丢失未保存内容。路由正常成功或应用卸载释放恢复状态和监听。

## 验收

除新页面冒烟外，必须使用前一版本的首页/入口 JS，房间懒加载资源与业务 API 仍请求实际服务器，验证旧页面进入新部署后可用。仅忽略异常或强制让测试浏览器刷新不算此项通过。

同时验证脚本404时页面有提示、没有自动刷新循环、没有发业务或设备请求；显式恢复后重新点击才能进入。保留旧资源并不能宣称所有无限寿命浏览器标签永久兼容。
