# 语音房P0投递预算与故障验证

本轮只验既有投递基础，不实施礼物账本、不更新生产。对应语音房方向P0及资金前置债务。

## 不变量与实际层

1. 每个人工代次最多十次领取；累计次数不归零。过期第十次确认未知转DEAD，活动租约不扫除。
2. 过期第九次仅一个竞争者可领取；旧令牌不能确认新租约。耗尽扫描单批最多100条。
3. 实际Broker停顿不能标SENT；恢复后保留相同事件标识重投。
4. Broker已确认但SQL确认失败，保留IN_FLIGHT，不把SQL故障写成Broker失败。
   未耗尽可过期重投，实际消息可能重复；本轮不宣称消费者幂等或恰好一次。
5. 原始异常秘密不进入last_error；保留异常类别和定位信息。

执行生产OutboxMapper XML、OutboxRelay、RocketMqEventSender及MySQL8/RocketMQ，
SQL造租约/到期时间仅为故障夹具，不冒充等待60秒或完整业务服务链路。

## 资源与回收

固定限权库/用户`koko_voicep0_outbox_20261005`，只复用现有MySQL。
两个私网Broker组件物理上限总384MiB，不使用Nacos/Redis，不开放主机端口。
本地只用127.0.0.1隧道与Java辅助进程。20分钟资源租约，内存保留350MiB、磁盘至少5GiB。
独立留存运行源码/映射/类/依赖摘要、成功失败日志、数据库备份、容器日志及生产前后摘要。
先备份校验，再回收固定测试库/账号/标签校验的容器与私网；保留历史验收目录，不宽泛清理。

## 剩余边界

真实语音媒体、Gateway与voice全链路、跨节点聊天/房间事件、告警送达、资金账本、HTTPS、
浏览器和容量不由本次测试证明。先前绑定凭据协议仍未验收，不发布其新JAR。
