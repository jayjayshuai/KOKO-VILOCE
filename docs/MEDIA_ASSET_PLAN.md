## 领域不变量

1. 上传只能由 Gateway 已登录用户发起；下游只信任 Gateway 重写的 `X-Koko-User-Id`。
2. 仅接受不超过 5 MiB 的 JPEG/PNG；文件名扩展名、声明 MIME、内容魔数及图片解码器
   必须一致。长边不超过 4096，像素总数不超过 800 万，重新编码后的大小仍须符合上限。
3. 对象键由服务端生成，调用方不能指定键或覆盖其他对象。资产 ID 和所有者写入 MySQL。
4. 资产只有 `READY` 才可读；所有者可读私有草稿，其他访问者须有真实公开引用，
   否则返回 404；无法核验公开状态时返回 503，不暴露对象键或永久凭据。
5. 数据库和对象存储不具备原子事务：先记录 `PENDING`，再写对象，最后 CAS 到 `READY`；
   未完成的 `PENDING/CLEANING` 由对账任务删除对象后清表，失败保留供下一轮重试。
6. 当前可用性仅为单节点阶段环境，不宣称多副本高可用或正式生产上线。

## 上传配额与内存保护（已部署）

默认每人 100 张/100 MiB、KOKO 桶合计 10000 张/1 GiB；
`asset_usage` 与 PENDING 意图在同一 MySQL 事务中登记，先锁定桶预算再锁定个人预算，
用条件 UPDATE 保证并发不能超配。对象写入不持有数据库锁；失败 PENDING 继续占用额度，
直到删除对象并在事务中清理意图时释放。清理重复执行不能重复扣减。
V3 对历史 PENDING/READY/CLEANING 回填预算，部署迁移时必须停止旧版本资产写入者。
2026-10-01 已部署资产 Flyway V3，并在真实账号验收中核对个人字节数/张数和其他用户隔离。
`GET /api/assets/images/quota` 返回本人预算，前端图片库展示用量。
个人超额返回 409 `ASSET_QUOTA_EXCEEDED`，桶容量不足返回 503 `ASSET_STORAGE_CAPACITY`。
头像/封面解绑不立即释放额度；对象仍保留，需待安全的生命周期清理完成后释放。

单实例最多处理一个上传（从解码到对象写入完成），竞争请求返回 429 `ASSET_UPLOAD_BUSY`
及 `Retry-After: 2`；任意异常均释放处理许可。ImageIO 重编码使用有上限的随机访问输出流，
在写入过程中拒绝超过 5 MiB 的缓存，避免事后大小校验先耗尽堆内存。

最新受影响模块 31 项单元测试及 Vue 构建通过；临时 MySQL 库运行实际 MP 映射器和 Spring
事务代理，验证 16 路并发、个人/桶分别按字节与张数拒绝、插入失败回滚和重复清理。
临时库、限权测试用户和凭据文件已清理；公网验收数据及其配额占用已清理，
`verify-asset-accounting.sh` 复查账本差异为零。
发布备份为 `/srv/deployment-home/koko-nexus-release/backup-stage3-quota-20261001a`。

下一批绑定/清理并发不变量：

1. 绑定必须先在资产库持久登记占用意图，并与 READY→RETIRING 的领取使用同一资产行锁；
   域事务结束前不可释放占用。RPC 响应丢失或域提交结果未知时保留意图，不能仅按 TTL 清除。
2. 无绑定意图且满足保留期才能 CAS 到 RETIRING，阻止新的绑定，再核验两域全部引用。
   有引用恢复 READY；核验故障不得删除对象。RETIRING 必须区别于现有失败上传 CLEANING，
   不能被旧上传对账任务直接物理删除。
3. 仅已取得绑定围栏且两域均确认无引用的正确执行代次，才进入对象删除/事务额度释放；
   对象故障保留可重试状态，元数据/额度按受影响行数幂等释放，并记录审计。
4. 旧写入者未升级/停写之前，READY 清理开关必须关闭；补真实 MySQL 行锁/提交顺序、
   RPC 结果未知、私有引用、对象删除失败和恢复演练后，才考虑启用。完整清理协议尚未实现，
   不能把两个域的查询结果直接接到现有 storage.remove。
