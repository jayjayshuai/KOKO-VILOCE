# 更新后旧页面入房无响应修复（2026-10-11）

## 定位与修复

用户反馈中午可用，晚间在手机点击入房没有反应。以旧版本入口页面、390像素触摸视口及真实测试账号复现：请求旧 VoiceRoomView 哈希脚本得到404，路由留在语音目录，JOIN数量为零。不是据手机机型猜测故障；尚未直接检查用户实体手机。

先恢复两个此前已验证版本的哈希资源，保留当前首页及全部新资源。相同文件名先核对摘要，恢复不覆盖冲突文件；只重建静态 Web，Java、中间件及数据库结构未变。

随后增量发布隔离的修复候选：页面加载失败提示与明确刷新入口、首页 no-store，以及缓存房间从目录再次明确选择只收听时恢复连接。既有创作者功能暂存未混入此发布。

## 实际验证

- 精确修复树 8a17fc9eeac77041b3905ba3a4d93edb666594a5：277项前端测试通过，0失败/跳过，类型检查和构建通过；保留 LiveKit 单包体积警告。
- 旧首页与入口JS仍用原版本，房间脚本、业务API、SDK/WSS均访问实际服务器。修复后旧脚本200、JOIN一次，实际声音连接成功；未忽略TLS。
- 触摸视口下，仅对测试页面的房间脚本注入404：恢复提示可见，无自动刷新，无JOIN，无麦克风采集。用户明确确认刷新后，再点击收听连接实际SDK。
- 已连接听众合成离线/恢复事件后，从目录明确点击只收听，恢复同一房间；JOIN不重复、采集为零。不以合成事件替代实体手机弱网认证。
- 候选及线上恢复页面流程均验证，旧入口页面线上再次复验。线上新构建逐文件摘要及首页no-store另行记录在私有运行证据中。
- 发布前备份、摘要、隔离Nginx配置验证和HTTP/TLS边缘检查通过。旧哈希资源继续提供，未自动结束已有通话。

原测试首次恢复复验点击早于身份恢复完成，出现登录表单；补齐等待账户恢复后再点击的测试前置条件，通过真实旧页面链路。失败不算通过，也不将其归为用户账号故障。

原始截图、登录账号、Cookie、JWT、服务器地址、发布备份和日志仅留私有目录。本轮没有启动私有 prod 配置、执行迁移或修改用户现有业务对象；联调自建房间关闭、测试会话退出确认。
