# 聊天浏览器双端验收计划

2026-10-05进行中：延续真实Gateway/共享会话证据，补生产前端的实际页面运行。
不替代完整企业路线、可见窗口人工体验、TLS或容量验收。

## 不变量

- 两个独立浏览器Context/不同环回主机名，不复用用户浏览器档案、真实账号或令牌。
- 运行冻结的生产构建，真实HTTP/WS到四Boot、独立Nacos/Redis和两套限权SQL；
  不截获请求返回假数据，不修改组件内部状态/计时器来制造成功。
- ACK后才显示已保存；接收端重取事实，断线/恢复不能重复展示或把故障当成功。
- 同步/连接/写入错误分别恢复，不清除与该恢复无关的错误。
- 成员失权后清除历史、禁用旧会话操作；重新入群不可读加入前历史。
- WS确认会话失效必须通知应用鉴权边界，卸载私有页面，而不只是停止后台读取。
  捕获连接时的身份/会话轮次，迟到失效不能注销同账号新会话。
- 注销、切页、卸载释放连接/订阅；移动视口、键盘与文本转义在实际DOM中验证。

## 执行

先用未修复构建记录失败，再修复真实问题，执行SFC/类型/构建与浏览器复验。
使用程序化独立无头Chromium；内置浏览器操作工具初始化失败，按恢复规范重试/重置后
停止操作现有浏览器。无头页面检查不是可见窗口人工视觉或真实移动设备认证。

测试只使用生成的合成账号/内容，不保存HAR、trace、Cookie、密码或登录响应。
截图在登录完成后生成；API辅助只用于注册夹具/撤销/对账，不伪造UI成功。
操作本轮中间件/节点做故障注入，不暂停生产资源；先备份，再定向清理并核验。
隐私检查仍使用临时Git index，不自动推送或发布未验收配置。
