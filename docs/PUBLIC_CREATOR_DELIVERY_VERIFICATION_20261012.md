# UP主公开主页交付（2026-10-12）

## 已实现并发布

- 增加可分享的`#/creators/:slug`公开详情页，从既有Java Gateway/Dubbo/身份域接口直接读取ACTIVE主页；不拿发现列表或本人草稿代替详情。
- 创作者卡片名称、本人工作台“查看公开主页”、已关注列表均提供详情入口。未发布主页不展示本人公开查看按钮，草稿仍在私人编辑器维护。
- 完整展示名称、短介绍、多行简介、服务端粉丝数，以及绑定的受管头像/封面；文本转义，不执行HTML。新页面不加载任意外部协议的历史图片URL。
- 提供公开地址、用户点击复制及失败后手动选择地址的提示；地址来自当前站点和已确认slug，不硬编码部署服务器。
- 匿名“登录后关注”打开已有登录表单，不自动关注；本人提供维护入口，其他账号先GET核验关系后才可关注或取消。
- 关注回应丢失或错目标/状态时保留核实门禁，不自动重发；原有确认值不能当新写入已成功。查询关注状态独立于主页投影，未核验不能基于默认false提交。
- 路由slug、账号、同账号新登录轮次隔离；取消旧读取，迟到GET/写回应不能污染新主页、解除新流程或向新作者提交。卸载不再发起新请求。
- 公开主页及本人关注GET均no-store、支持取消；校验公开状态、地址、身份ID、文本类型/长度和计数/版本。无效地址不联网，404或失败提供明确重读，不展示上一作者资料。

本次发布仅前端，不改Java服务、RPC协议、生产结构及开关，未重启Gateway/身份/资产/Voice/Nacos，未启动本机私有prod配置。直接业务API在专用测试账号下产生数据，没有直接SQL写入；不是“没有数据库写入”。

## 失败尝试与恢复边界

首次带两张图片的主页保存返回503，日志出现5秒RPC超时；没有自动重发原保存。随后只读查询同一专用账号，取得DRAFT、有效版本及两张绑定图片，说明该次服务端写入实际完成，HTTP失败不能当回滚。

继续从已确认草稿检验发布时，自动化在原生“重新读取将覆盖表单”确认处默认取消，未产生所期待的GET恢复，测试超时。另一新样本完整跑到同一确认处也未完成；这是测试脚本缺少确认处理，不称产品恢复验证通过。修正脚本仅接受已明确选择的原生覆盖确认后，用全新候选和线上样本完成整套验证；不是取消保护、隐藏错误或把早期失败报告改为PASS。

首次RPC超时预算仍未调整。本轮后续暖运行成功不证明首次调用、慢网或高负载均满足当前预算；外层调用与资产绑定/数据库的耗时预算、容量与监控还需单独优化，不能笼统归因于浏览器。

已读/关注关系GET是当前服务端事实，不是原写入的幂等收据。多窗口或服务端迟到执行仍可能随后改变关系；本页未知状态仅留当前生命周期内存，不保证跨刷新持久恢复或恰好一次。公开资料是查询快照，不保证公开撤销后已下载内容从浏览器消失。

## 测试资料与下一阶段

本轮全部业务写入限定专用合成账号。首次失败草稿、公开验收主页、受管图片、关注通知和历史仍保留；公开资料明确标为“验收专用”，不含真实个人资料。现有接口没有主页下线/删除能力，不直接改SQL伪造清理。已注销测试会话，语音测试房关闭确认；未删除其他用户数据。

作品按作者的有界列表、主页主动下线/审核/恢复、遗留外部图片、跨刷新幂等收据、批量互动、多节点容量、物理手机锁屏及真人音质仍未验收。上一轮磁盘压力、Nacos管理登录异常、直播与Discord外部前提也不因本轮详情页完成而消失。

既有公开接口的固定`/discovery/creators/page`与主页slug为`page`的情况存在路径冲突；本轮没有改Java路径或对该slug作正式验收，详情校验会拒绝分页投影，后续需采用独立查询路径并兼容旧客户端。新页面关注门禁不代表发现卡片/旧集合等其他入口的全部关系恢复也已重构。

使用：在“创作者”点击名称查看主页；本人“内容工作台”保存并发布后选择“查看公开主页”。其他账号先核验关注状态，再关注；结果未知选择查询，不反复提交。可运行`npm --prefix web test`、`npm --prefix web run build`、`npm run test:format`及`npm run check:secrets`复验公开代码；生产验收需要自己的受信服务与私有测试凭据。
