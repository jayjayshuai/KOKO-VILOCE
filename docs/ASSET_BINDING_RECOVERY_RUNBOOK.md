# 绑定释放人工恢复运行手册

目前仅源码与隔离验证通过，生产未开放。先完成[剩余门槛](ASSET_BINDING_RECOVERY_VERIFICATION_20261005.md)。
不得在现有公网HTTP输入运营密码。本手册不授权任意赋权、公开管理端口、停共享中间件或删除生产资产。

## 发布准备

1. 负责人指定最小权限账号，走已有角色变更/确认/审计；通知管理员不是资产恢复员。
2. 完成域名TLS/WSS、Secure/HttpOnly/SameSite/CSRF及可信代理检查；浏览器HTTPS只是外层条件，
   还要确认Gateway/代理/身份RPC秘密传输与请求体日志保护。
3. 备份两业务库/资产库与旧JAR/Web/配置，隔离恢复比较账本、任务、审计和结束标记。
   两域V14与资产V5前置满足，已执行Flyway不编辑。
4. 停两域全部旧worker；迁移两域V15/身份V16，升级全部新Provider，再Gateway/Web。
   旧版本attempts<10不支持人工代次，禁止混合启用；不删除迁移或清零计数作为回滚。
5. 默认关闭验证后先开放读，再批准恢复；`OPERATIONS_ENABLED`、
   `ASSET_BINDING_OPERATIONS_ENABLED`、`ASSET_BINDING_REPLAY_ENABLED`同时控制写。
   `ASSET_BINDING_RELEASE_ENABLED`独立控制worker，不同时打开READY删除。

## 单条操作与结果未知

1. 固定域读取原requestId事实与审计，确认故障根因处理完。requestId是原业务提交凭据，
   不用资产ID或人工commandId替代。仅无租约、DEAD、本代10次耗尽、代次<10可准备。
2. 填工单原因10～500字符，记录完整业务域、requestId、commandId、原代次、规范化原因。
   不记录密码、票据、会话或租约秘密。准备只是生成未发送命令。
3. 本人密码确认五分钟票据，再单独受理。错误密码仍占独立预算，频繁确认429。
   202只表示排队；刷新原任务到PENDING/LEASED/SENT/DEAD，SENT不是对象删除/额度归零。
4. 超时/取消不证明回滚，保留原命令，先查事实；404只是未观察到，禁止换ID盲重试。
   匹配操作者、代次、原因后确认原受理。未知后的403/409仍不丢命令。
5. 内存原命令跨路由保留，秘密切页清除；刷新/退出不持久保存命令。
   刷新后“重录已保存的原命令”须原字段，不猜代次/原因；重录强制未知且不写，先查再
   在当前权限下确认同一命令并幂等重试。审核员可重录查询，不能发送密码/受理。
6. 没有原记录时先按requestId读取审计，不能凭空造新命令替代。
   退出后原操作者重新认证；另一账号不能把别人的命令当本人命令恢复。

## 故障边界

- SQL/审计失败返回不可用仍先查原命令；隔离TX回滚测试不证明任意网络超时已回滚。
- 关闭恢复开关保留任务、次数、审计/结束标记。新代次受理后不能换旧worker，需暂停并向前修复。
- 授权检查不能追撤已授权在途事务；撤权后仍可能看到合法在途提交。
- 两域引用快照不是删除许可；未知意图、READY/RETIRING完整生命周期另行验收。

操作留原命令/工单/审计/最终事实/版本/时间，监控积压与固定失败类别。
真实告警receiver、责任人响应与异地恢复演练尚未通过，不能以同机备份宣称高可用。
