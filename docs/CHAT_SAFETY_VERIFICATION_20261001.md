## 本轮交付

前端消息中心增加安全中心、本人拉黑列表和解除、按公开用户名拉黑、他人真实消息举报、本人举报进度，以及按服务端能力显隐的人工审核界面。包含真实加载/失败/成功反馈、取消旧读取、卸载取消请求、旧响应代次隔离和写入防重复提交；安全中心打开时不把隐藏聊天历史自动标记已读。前端只限制本人的已知设置，服务端仍执行双向授权。

Java chat-service 新增 Flyway V2、MP 实体/映射与 XML 事务锁。拉黑与新私信发送在共用用户对锁下串行化，授权必须当前读，不能使用旧 RR 快照。双向新私信及相互群邀请被拒绝，原已提交 UUID 重试返回原事实；已有共同群仍可见，历史不被擦除。不存在关系的幂等解除不生成任意用户对行。

举报目标、正文证据取自数据库，当前成员与入群边界校验；每人每条消息一份，新举报滚动 24 小时最多 20 份，主动拉黑最多 1000 个。普通接口只返回本人的进度，不序列化证据、举报人/审核员身份。审核入口重新校验共享 Sa-Token 与可信身份，版本化最终决定和只追加审计同事务，不可自审，结案不自动封禁。

实体使用 Lombok Getter/Setter，不生成敏感 toString；新 Java 字段与 HTTP Tag/Operation/Schema、前端业务契约字段补中文语义。沿用 Java/Nacos/Dubbo/Gateway/Sa-Token/MP，不新增 JVM，不替换自建 LiveKit。

- 最新全模块 `mvn -q test` 退出码 0：111 项，27 个测试套件，失败/错误/跳过均 0。故障注入日志中的 database offline 不是线上状态；本地 JDK 25 有既有 Unsafe/Mockito 警告，服务器为 Java 21。
- Vue TypeScript 与 Vite 生产构建通过；主业务 JS 约 156 KiB，LiveKit 动态包约 583 KiB 的体积告警仍存在。
- Java 契约审计 `patches=[], fallbacks=[]`，前端基础契约审计 `patch=null, missing=[]`；新安全契约人工检查字段语义。这不是全系统每个函数完成文档治理的证明。
- 真实 TCP Netty 用例覆盖拉黑拒发 ERROR/FORBIDDEN、不返回成功 ACK；该协议测试中的业务服务采用 mock，数据库事务另由真实 SQL 测试证明。
- 隔离真实 MySQL：24 路并发消息序号和原核心边界；双向拉黑/邀请/重试；真实证据、举报唯一/权限/入群边界；旧版本拒绝、同决定重试、不可自审；24 路举报只接受 20 份；两个审核员竞争只产生一个最终审计；审计写入失败完整回滚状态/版本；999 个拉黑关系加 8 路竞争只接受一个；先建立旧 RR 快照再提交拉黑，发送被拒绝且消息/序号均不提交。
- 审计故障注入最初使用触发器，被共享 MySQL 的 binlog/SUPER 限制拒绝。改为隔离 schema 内的临时 CHECK 约束注入失败后全部重跑通过，未提升用户权限、未改共享数据库全局配置。最终临时 schema/数据库用户/凭据文件全部清理。
- 公开核心 `chat-stage-smoke.ps1`：56 项断言通过，覆盖真实 Gateway/Redis/Netty/MySQL、群权限、历史边界、七组文档及注销撤销。
- 公开安全 `chat-safety-smoke.ps1`：60 项断言通过，覆盖匿名拒绝、双向拒发、原 UUID ACK、不消耗序号、阻断/恢复邀请、举报幂等/冲突/归属隔离、默认无审核权限/伪造头拒绝、共同群与入群/移除边界，以及 OpenAPI 新路径。前两次安全验收在未知用户名的预期状态码处停止；校准为现有身份目录的 400 拒绝语义后，第三次完整通过，不把失败尝试算成通过。

- 公网首页、新版 JS/CSS HTTP 200；九个带健康检查的 KOKO 容器均 healthy，当前容器 OOM=false、restart=0。LiveKit 的运行状态不替代 RTC 双客户端验收。

## 必须保留的上线门槛

审核员配置仍为空，普通账号均不能访问审核证据。正向审核事务在隔离 MySQL 通过，控制器权限/身份校验有测试；没有把生产用户擅自设为审核员，也没有完成公开正向审核验收。负责人应指定已注册公开用户名，解析实际 ID、配置最小权限后再验证真实证据读取、最终结案、本人进度更新及撤权。审核说明会展示给举报人，不应包含内部信息、证据复制或无关个人隐私。初期明确 ID 配置不是持久化、动态运营 RBAC。

浏览器曾能读取匿名首页，但随后刷新/绑定连续超时，未完成真实 UI 点击、布局或移动端验收。源码/构建/API 通过不能代替该项。

公网仍为 HTTP，正式运营前必须域名、HTTPS/WSS、安全 Cookie 与密钥轮换。账号封禁/申诉、合规留存、完整 RBAC、跨节点分发、容量/慢客户端测试、异地备份与恢复、外部告警，以及 Discord/实际视频直播链路仍有独立未完成项。

服务器采样：物理内存 3718 MiB，available 1073 MiB，swap 14335 MiB（已用 8827 MiB）；磁盘可用 8.8 GiB、使用 85%。这些不是容量承诺，扩 swap 不等于增加物理内存。本次没有新增 JVM；不因默认保护阈值而宣称服务器承载相应并发。

V2 上线后不得直接降级为不执行拉黑的旧 chat 继续写消息。失败时先停聊天写入、保留事实与迁移、优先向前修复，详见 [发布手册](CHAT_RELEASE_RUNBOOK.md)。
