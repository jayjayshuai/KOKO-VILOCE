# KOKO Nexus 实施计划

## 产品边界

KOKO Nexus（可可星联）是面向创作者与兴趣社区的实时语音、直播和内容平台。本阶段交付可部署的
微服务基础与首条真实业务闭环，不以静态演示数据或默认管理员替代功能。

## 技术边界

- Java 21 与 Spring Boot 3.5 为主业务运行时。
- Gateway 使用 Spring Cloud Gateway 与 Sa-Token，统一登录、鉴权、限流并删除客户端伪造身份头。
- Nacos 负责服务发现与配置隔离，Dubbo 负责内部 RPC。
- MyBatis-Plus 负责简单数据访问；复杂查询和状态迁移使用 XML SQL。
- MySQL 按服务隔离逻辑数据库，Redis 存储 Sa-Token 会话。通知域已接入 RocketMQ 与事务 Outbox，但独立故障演练尚未完成。
- MinIO 已接入受管 JPEG/PNG 资产服务及头像/封面绑定、本人图片库、发布引用授权读取；
  个人/桶级事务配额已部署；预签名 URL 与 READY 孤儿清理尚未完成，实时媒体流不经过 Java 业务服务。

## 业务不变量

1. 网关只注入由 Sa-Token 确认的用户身份，客户端提交的同名身份头必须先删除。
2. 业务服务不能只信任网关角色；创建、修改和删除必须再次核对资源归属与状态。
3. 同一邮箱、用户名、UP 主主页地址和社区 slug 在并发请求下仍只能创建一次，由数据库唯一约束兜底。
4. 直播状态只能按 `SCHEDULED -> LIVE -> ENDED` 演进，旧请求不得覆盖终态。
5. 通知域将业务事务与消息投递分离，并通过 Outbox 重试；故障恢复、死信重放和异地备份仍是上线门槛。
6. 未配置 Discord 或媒体供应商时明确返回能力不可用，不伪造连接、直播或推流成功。

## 暂不承诺

- 未经容量测试不承诺并发规模或高可用等级。
- 未接入真实直播供应商前，不宣称视频推流链路已验收。
- 单机部署不是高可用；后续需至少双节点、外置数据库与对象存储才能形成容灾。
