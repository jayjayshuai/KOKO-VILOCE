# 创作者地址与保存预算修复交付（2026-10-13）

## 本轮实现并发布

- 新增Java公开`GET /api/discovery/creators/by-slug/{slug}`，前端公开主页使用独立详情路径，合法slug为`page`不再误读分页投影。原分页及原详情接口保留，旧普通主页客户端兼容；旧客户端的`page`冲突不能在不破坏分页的前提下原地修复。
- 新路径校验3～64位地址，非法参数400，不存在/未发布404。只调用既有身份域公开查询，不读私人主页作降级，也未修改其SQL状态过滤。
- 仅`saveCreatorProfile`外层Dubbo预算由5秒改为15秒，给两次最多5秒的资产保护调用和事务/调度预留空间；读、发布及关注仍5秒，retries仍0。浏览器总等待20秒不改，不扩大全部RPC超时或自动重发写入。
- RPC故障按注册、读取、其他写入分别返回安全提示。主页失败不再提示“注册可先尝试登录”；写入未知明确要求先查询、不重复提交。路径/查询约束失败固定400消息，不回显拒绝值或堆栈。
- STRICT白名单仅增加`SaveCreatorProfileCommand`、`CreatorProfile`、`CreatorPage`、`CreatorFollowState`四个已声明具体契约，无包前缀豁免或检查降级。

只发布新Gateway和冻结前端。其他Java服务、Nacos/Redis/数据库/资产存储/LiveKit未重启，生产配置、密钥、媒体开关、数据库结构保持原值。没有直接SQL写入或迁移；专用业务API验收会正常写入业务数据。

## 首次失败与实际回滚

专项测试最初10项通过，第一份全套Gateway候选104项中1项错误：STRICT拒绝缺少白名单的SaveCreatorProfileCommand。没有跳过该测试、放开包或改为宽松模式；增加四个具体契约及编解码回归后重新冻结并执行上表全套候选。

第一轮Gateway更新的容器健康检查通过，但脚本使用HTTP探针访问受HTTPS策略保护的入口，返回426并触发回滚。保留该轮失败报告；旧Jar恢复、旧镜像重新标记/启动，公网原分页200确认。该次不是新后端成功发布，也没有关闭TLS策略掩盖脚本错误。

修正私有发布探针为带证书校验的HTTPS后，以新目录再次部署同一精确Jar，成功。保留两轮旧Jar/Compose摘要、旧镜像标签和私有检查记录；当前成功版本与备份摘要核验通过，身份/资产/Voice/Nacos容器ID不变。前端只在新接口和候选实际验证后发布，合并旧哈希资源，同名摘要一致；备份、隔离Nginx及边缘检查通过，前端未触发回滚。

Gateway单节点替换与第一轮回滚都可能短暂影响入口；不能因观测到无通话就宣称零停机或零影响。没有删数据库、事件历史、其他容器/镜像、旧回滚包或用户数据。

## 范围与后续

按企业开发规范分开对待读取、写入未知、业务提交和发布验收。本轮预算只是给嵌套调用留有界等待空间；不能保证15秒内一定完成，客户端等待结束也不代表服务器停止执行。跨刷新请求收据、多窗口并发、RPC逐跳总deadline传播及持续延迟/容量观测仍需独立实现。

测试账号、验收专用公开page主页、其他测试主页/图片、通知和历史均保留；会话注销、临时语音房关闭确认。没有主页下线接口，未用直接SQL伪造清理。凭据、原始日志、截图、配置快照和备份仅留私有目录；本轮未提交既有Voice Mapper、路线文件或面试资料改动。

主页主动下线/审核/恢复、按作者有界作品列表、完整直播/Discord、实体设备后台策略、外部告警及异地恢复继续保留门槛。磁盘压力和Nacos管理登录异常不因本次接口成功而认定已解决。

复验公开源码：Java21下执行`mvn -f backend/pom.xml -pl gateway-service -am package`，以及`npm --prefix web test`、`npm --prefix web run build`、`npm run test:format`、`npm run check:secrets`。生产联调需要自己的私有凭据及隔离验收账号；不以测试桩替代真实HTTP/队列/媒体证据。
