# 语音房互动核心阶段计划

沿用语音P1方向，先完成可持久验证的成员/麦位/幂等/审计与管理页面。
默认`VOICE_INTERACTION_CORE_ENABLED=false`；媒体授权、撤销/补偿、事件通道未完成，
核心开关不是正式运营开关，SQL麦位状态不是LiveKit发声权限。

## 本轮边界

- 新V3增加CONTROLLED模式、单调房间版本、成员会话、八麦位、申请/邀请、命令收据和审计。
  老房间保持LEGACY，禁止原房间转换，避免旧发布JWT绕过新控制；受控房间不能走原JWT接口。
- 可信网关身份，房主/房管/听众角色与上麦态分开。全部命令锁同一房间行，成员/席位/收据
  当前读，SQL版本检查、状态改变和追加审计同事务；无外部媒体I/O持锁。
- 长期房管最多8名，可离线撤权；转让后旧房主权限降为房管，不复用旧RR角色快照。
- 关闭先持久CLOSING冻结归属，媒体删除/确认分离；未知失败保持意图，后台补偿仍未实现。
- 单用户一份房间会话，90秒租约；旧session不能续期/操作新会话，过期不得复活。
  预约60秒；快照/命令按数据库时钟惰性回收。不是媒体服务器在线人数或后台定时回收验收。
- APPLY/INVITE/PULL、ACCEPT/REJECT/CANCEL、DOWN/KICK/MUTE/LOCK、LEAVE、ADMIN/TRANSFER，
  服务端做状态/归属/层级限制，客户端按钮不当安全边界。
- 命令UUID+指纹同事务收据，原UUID改参数冲突，成功重试不重新变更；房间版本不倒退。
  单人单房间最多1000收据（退出可额外一次），每10秒最多10个新命令；无无限重试。
  上线前须明确保留/归档，不能把保护阈值当容量或永久幂等承诺。
- 前端单写、原请求重试、独立读写故障、切账号/会话/房间隔离；受控模式不请求旧媒体JWT。
  页面明确媒体未开放，不显示“已发声”或假在线。

## 必须验证

实际MySQL迁移/行锁、抢位/人数、旧RR快照撤权、收据/审计故障回滚、过期会话/预约与自然租约；
HTTP可信头/校验、Vue异步状态及页面检查、全量构建/格式/隐私。先保存失败证据，定向备份后清理。
通过局部范围后阶段提交；真实媒体/多实例事件/RTC/TLS、容量与上线仍保持未完成。
