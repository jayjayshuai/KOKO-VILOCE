# 聊天全局连接租约验证记录

2026-10-05，本批代码未发布，生产仍使用旧聊天版本。按企业开发规范把单元测试、
真实Redis/Netty行为、清理恢复和正式上线门槛分开；不以格式或编译代替运行验收。

## 实现范围

Java chat服务新增共享Redis单用户三份有效连接租约；每连接独立服务端UUID，
单键Lua执行，Redis TIME计时，120秒有效期。PING/SEND先重验证共享登录再续期；
不存在/过期UUID不得续活，旧释放不能删除新连接。Redis故障或未知结果失败关闭，
不用本机计数作为降级。保留本机三连接与500总连接快速防护。

Redis和身份I/O均在双线程/128队列的业务池，停止/迟到握手由生命周期轮次隔离；
关闭幂等释放，释放入队失败计数并依靠TTL，不另起无界线程。会话类用Lombok构造器，
不生成含令牌的toString/序列化访问器。新代码字段有中文用途/边界注释。
没有新增HTTP契约或SQL迁移，既有Knife4j与聊天事务权限不改变。

前端`CONNECTION_EXPIRED`只更新连接错误，不注销账号；READY清理连接提示，
发送/管理错误仍保留，断开后待确认消息使用原UUID重试。浏览器WebSocket API不暴露
完整失败握手状态，当前429/503显示通用连接失败，不能声称已有精确配额弹窗。
参考[WebSocket标准](https://websockets.spec.whatwg.org/)。

## 原失败与独立恢复

根行为助手及两子节点正常结束，六组PASS均已记录。但原编排最终退出1：
自动清理SAVE时普通用户无法写root所有的`/data`，原收尾未通过，不能记为自动收尾成功。
第一次独立恢复仅修复精确测试容器的tmpfs权限，SAVE成功；Docker cp未读取到该挂载上的
文件，恢复仍失败且保留原容器，不删除未备份数据。
只读检查确认实际89字节RDB存在后，第二次独立恢复通过无TTY docker exec读取固定文件，
内外SHA-256一致并通过redis-check-rdb，才正常停止/移除原ID容器及原ID网络。

已验证本轮测试容器/网络/随机凭据文件移除，本机转发26489与两子节点不再存在。

## 仍需验证和发布

所有节点须升级并共用同一Redis；混合旧版节点仍可能绕过全局限制。有效租约不是
物理设备或任何故障下TCP总数承诺，不是数据库提交围栏。Redis重启/主从切换、数据丢失、
时钟跳变、实际ACL/持久化配置及JVM长暂停仍须演练；TTL不等于所有故障下可靠释放。
生产Prometheus/外部告警、压力/慢客户端/持续容量、完整Boot/Gateway会话与SQL、
本次新增提示的正向浏览器/移动端、发布/回退和公网HTTPS/WSS仍未通过。

不等于服务器发布或本节验收门槛通过。
